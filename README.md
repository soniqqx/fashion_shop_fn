> เว็บหน้าร้าน E-commerce (Storefront) พัฒนาด้วย Next.js (App Router) เชื่อมต่อกับระบบ E-commerce Backend API สำหรับเลือกชมสินค้า จัดการตะกร้าสินค้า และสั่งซื้อสินค้าแบบแบ่งขั้นตอน (Multi-step Checkout)

**สถานะ:** กำลังพัฒนา (Work in Progress) — รองรับการแสดงรายการสินค้า, ค้นหาและกรองหมวดหมู่, จัดการตะกร้าสินค้า, และขั้นตอนสั่งซื้อพร้อมชำระเงินจำลอง

---

### Interactive guide: ลอง flow ฝั่งลูกค้า

```text
1. เข้าสู่ระบบที่หน้า /login ด้วยบัญชี CUSTOMER
   │
   ▼
2. เลือกดูสินค้าจากหน้าแรก (/) หรือหน้าสินค้าทั้งหมด (/products)
   │  เลือกตัวเลือกสินค้า (Variant) และกด "+ ตะกร้า"
   ▼
3. เปิด Cart Drawer มุมขวาบน หรือไปที่หน้าตะกร้าสินค้า (/cart)
   │  เลือกสินค้าที่ต้องการชำระเงิน (สินค้าที่หมดหรือถูกปิดการขายจะถูกล็อกไม่ให้เลือก/แก้ไขจำนวน ลบได้อย่างเดียว)
   ▼
4. ขั้นที่ 1: ที่อยู่จัดส่ง (Address & Shipping)
   │  เลือกที่อยู่เดิมหรือกรอกที่อยู่ใหม่ + เลือกรูปแบบการจัดส่ง (Standard / Express)
   │  เมื่อกดดำเนินการต่อ ระบบจะเรียก POST /api/checkout เพื่อสร้าง Order และจองสต็อก
   ▼
5. ขั้นที่ 2: ชำระเงิน (Payment)
   │  ตรวจสอบยอดรวมและรายการสินค้าทางคอลัมน์ขวา
   │  กดยืนยันชำระเงิน (POST /api/payments/:id/succeed) หรือจำลองการชำระเงินไม่สำเร็จ
   ▼
6. ขั้นที่ 3: เสร็จสมบูรณ์ (Done)
   └─ แสดงสถานะคำสั่งซื้อสำเร็จและตัดสินค้าที่สั่งซื้อแล้วออกจากตะกร้า
```

## System flow

### การจัดการตะกร้าและการตรวจสอบสถานะสินค้า

```text
[ProductCard / Products Page]
       │
       │ กดเพิ่มลงตะกร้า (addToCart)
       ▼
[CartContext] ──► POST /api/cart-item/create
       │
       ▼
[หน้าตะกร้าสินค้า (/cart)]
       ├── สินค้าปกติ (isActive: true & quantity > 0)
       │     └─ เลือก Checkbox สั่งซื้อได้ / เพิ่ม-ลดจำนวนได้ / ลบได้
       │
       └── สินค้าไม่พร้อมจำหน่าย (isActive: false หรือ quantity <= 0)
             └─ แสดงป้าย "สินค้าหมด / ไม่พร้อมจำหน่าย"
             └─ ล็อก Checkbox ไม่ให้เลือกสั่งซื้อ และล็อกปุ่ม +/- (ทำได้เฉพาะกดลบออกจากตะกร้า)
```

### ตอนลูกค้าซื้อ: ขั้นตอนการ Checkout (3 Steps)

หน้า Checkout ใน `/cart` แบ่งโครงสร้างเป็น 3 คอลัมน์ (ปุ่มย้อนกลับซ้ายบน, ฟอร์มดำเนินการตรงกลางพร้อม Stepper, และสรุปรายการสินค้าที่สั่งซื้อทางขวา):

```text
[ขั้นที่ 1: ที่อยู่จัดส่ง] ──► [ขั้นที่ 2: ชำระเงิน] ──► [ขั้นที่ 3: เสร็จสมบูรณ์]
       │                            │                         │
  เลือกที่อยู่ + ขนส่ง          จำลองการชำระเงิน            แสดงผลลัพธ์คำสั่งซื้อ
  สร้างใบสั่งซื้อ (Order)     (succeed / fail API)        พร้อมเลขที่ Order
```

## Architecture

Frontend ใช้ Next.js Route Handler (`/api/[...path]`) ทำหน้าที่เป็น **Reverse Proxy** ส่งคำขอพร้อมแนบ Cookie (`access_token`) ไปยัง NestJS Backend เพื่อหลีกเลี่ยงปัญหา CORS และจัดการ HttpOnly Cookie ได้อย่างปลอดภัย:

```text
┌──────────────────────────────────────────────────────────┐
│                  Next.js Storefront                      │
│                                                          │
│  [Pages / Components] ──► [CartContext]                  │
│           │                     │                        │
│           └──────────┬──────────┘                        │
│                      ▼ (Axios Client)                    │
│        Next.js API Proxy (/api/[...path])                │
└──────────────────────┬───────────────────────────────────┘
                       │ Forward Request + Cookie Header
                       ▼
┌──────────────────────────────────────────────────────────┐
│            NestJS Backend (w_project_bn)                 │
│     Auth / Products / CartItem / Checkout / Payments     │
└──────────────────────────────────────────────────────────┘
```

## หน้าและโมดูลที่มีในปัจจุบัน

| Path / Module | หน้าที่หลัก |
|---|---|
| `/` | หน้าแรก แสดงแบนเนอร์ หมวดหมู่สินค้า และสินค้าแนะนำ |
| `/products` | หน้าแสดงรายการสินค้าทั้งหมด ค้นหาด้วย Keyword และกรองตามหมวดหมู่ |
| `/cart` | หน้าตะกร้าสินค้า และระบบ Checkout แบบ 3 ขั้นตอน (Address → Payment → Done) |
| `/login` | หน้าเข้าสู่ระบบ (`POST /api/auth/login`) และสมัครสมาชิก (`POST /api/user/create`) |
| `context/CartContext.tsx` | จัดการสถานะตะกร้าสินค้า ซิงก์ข้อมูลกับ `/api/cart-item/*` และ `localStorage` |
| `components/CartDrawer.tsx` | แถบตะกร้าสินค้าด้านข้าง (Slide-over Drawer) เปิดดูได้จากทุกหน้า |
| `app/api/[...path]/route.ts` | ตัวกลาง Proxy ส่งต่อ Request และ Cookie ไปยัง Backend |

## ปัญหาที่พบและข้อจำกัดในปัจจุบัน (Problems)

1. **การจัดการสินค้าที่หมดหรือถูกปิดการขายในตะกร้าสินค้า (`isActive: false` / สต็อกหมด)**
   - กรณีที่สินค้าหมดหรือ `isActive: false` หลังจากที่ลูกค้าเพิ่มสินค้าชิ้นนั้นลงตะกร้าไปแล้ว ลูกค้าไม่ควรกดสั่งซื้อสินค้า หรือกดเพิ่ม-ลดจำนวนสินค้าชิ้นนั้นได้ (ฝั่ง Backend ได้ดักกรณีนี้ไว้แล้ว และฝั่งหน้าบ้านได้อัปเดต UI ในหน้าตะกร้าให้ล็อกการเลือกและล็อกปุ่มแก้ไขจำนวน ทำได้แค่ลบออกอย่างเดียว)
2. **การแสดงผลสินค้าที่หมดหรือถูกปิดการขายในหน้า Product List**
   - กรณีที่สินค้าชิ้นนั้นสต็อกหมดหรือ `isActive: false` ไม่ควรนำมาแสดงในหน้ารายการสินค้า (`ProductList`) หรือควรแสดงป้ายสถานะชัดเจนว่า **"สินค้าหมด"** เพื่อไม่ให้ผู้ใช้สับสน
3. **การแสดงผล UI ระหว่างขั้นตอนการซื้อสินค้า (Checkout Flow)**
   - ปรับเปลี่ยน UI ตอนระหว่างซื้อสินค้าให้แสดงเป็นลำดับขั้นตอน (Stepper) อย่างชัดเจน แยกคอลัมน์ปุ่มย้อนกลับสู่ตะกร้า และแสดงรายการสินค้าที่กำลังสั่งซื้อควบคู่ไปกับฟอร์มที่อยู่และการชำระเงิน
4. **ยังไม่สามารถป้องกันกรณีที่ User กด Spam ซื้อสินค้าซ้ำสองรอบ (Duplicate Order Submission)**
   - หากผู้ใช้กดปุ่มยืนยันการสั่งซื้อรัวๆ หรือเน็ตกระตุกแล้วกดซ้ำ อาจทำให้เกิดการยิง Request สร้างออเดอร์ซ้ำซ้อนได้
5. **ยังไม่สามารถป้องกันกรณีที่มีคนมา Spam Call API (Rate Limiting)**
   - แนวทางแก้ไขคือต้องทำ Rate Limit โดยใช้ **Redis** เพราะหากเขียนโค้ดดักเองหลังบ้านโดยเก็บสถานะไว้แค่ใน RAM (In-memory) พอเรารีสตาร์ทระบบใหม่ ข้อมูลการนับก็จะหายไปและสามารถถูก Spam ได้อยู่ดี
6. **ยังไม่สามารถอัปเดตข้อมูลระบบแบบ Real-time ได้**
   - ในกรณีที่สินค้าหมดสต็อกกะทันหัน สินค้าถูกลบ หรือถูกเปลี่ยนสถานะเป็นไม่ได้ใช้งาน (`isActive: false`) ขณะที่ผู้ใช้เปิดหน้าเว็บค้างไว้ หน้าบ้านยังไม่ได้รับการแจ้งเตือนหรืออัปเดตสถานะทันทีแบบ Real-time
7. **ระบบการชำระเงินยังไม่สามารถตัดเงินได้จริง**
   - ขั้นตอนการจ่ายเงินยังคงเป็นแบบ Mockup (จำลองการกดยืนยันผลการชำระเงินสำเร็จ/ล้มเหลวผ่าน API เท่านั้น)
8. **การตรวจสอบกรณีที่ User Login แล้ว Token หมดอายุระหว่างใช้งาน**
   - ยังไม่สามารถเช็คและจัดการ Flow กรณีที่ผู้ใช้เข้าสู่ระบบค้างไว้แล้ว Token หมดอายุได้อย่างสมบูรณ์ (ต้องทำการทดสอบและดักจับ `401 Unauthorized` เพื่อเคลียร์สถานะหรือพากลับหน้า Login เพิ่มเติม)

## สิ่งที่ควรทำในอนาคต (Roadmap)

### 1. ระบบ Idempotency เพื่อป้องกันการสร้างออเดอร์ซ้ำสองรอบ
เราจะใช้วิธีแก้ปัญหากรณีที่เกิดการกดสั่งซื้อซ้ำ (Double Submit / Network Retry) ดังนี้:
- **ฝั่งหน้าบ้าน (Frontend):** เป็นคน Generate ค่า UUID สำหรับใช้เป็น `Idempotency-Key` แล้วส่งแนบไปใน Request Header ให้กับ Backend ตอนกดสร้างออเดอร์
- **ฝั่งหลังบ้าน (Backend):**
  1. **Redis:** ใช้คำสั่ง `SET` เก็บ Key `idempotency` ไว้ใน Redis เพื่อดักจับ Request ที่ยิงซ้ำเข้ามาพร้อมกันอย่างรวดเร็ว (Fast lock / Cache check)
  2. **Database:** เก็บค่า `idempotency` ลงในตารางฐานข้อมูลตอนที่สร้างออเดอร์ครั้งแรก (ภายใต้ Database Transaction เดียวกัน) เพื่อรับประกันว่าจะไม่มีการสร้างออเดอร์ซ้ำอย่างถาวร

### 2. ระบบจัดการเวลาหมดอายุของออเดอร์อัตโนมัติ (Order Expiration)
- ใช้ **Redis** (เช่น Key Expiration / Delayed Queue) หรือ **Background Worker (Cron Job / BullMQ)** ในการช่วยจับเวลาหมดอายุของออเดอร์ที่อยู่ในสถานะรอชำระเงิน (`PENDING`)
- เมื่อครบกำหนดเวลาแล้วยังไม่ชำระเงิน ระบบจะทำการเปลี่ยนสถานะออเดอร์เป็นยกเลิก/หมดอายุ และคืนสต็อกที่จองไว้ (`EXPIRED_RESERVE`) กลับเข้าคลังโดยอัตโนมัติ พร้อมมีหน้าประวัติคำสั่งซื้อให้ลูกค้าเข้ามาตรวจสอบออเดอร์ที่ยังไม่ได้จ่ายหรือหมดอายุไปแล้วได้

### 3. รายการพัฒนาเพิ่มเติมอื่นๆ
- [ ] ทำระบบ **Rate Limiting** ด้วย Redis เพื่อป้องกันการ Spam Call API
- [ ] เพิ่มการอัปเดตสต็อกและสถานะสินค้าแบบ **Real-time** (เช่น WebSocket หรือ Server-Sent Events) เมื่อสินค้าหมดหรือถูกปิดการขาย
- [ ] เพิ่มหน้า **ประวัติคำสั่งซื้อของฉัน (My Orders)** เพื่อให้ผู้ใช้กลับมาจ่ายเงินออเดอร์ที่ยังค้างชำระ (`PENDING`) ได้เมื่อกดย้อนกลับออกจากหน้า Checkout
- [ ] ทดสอบและจัดการ Interceptor เมื่อ **JWT Token หมดอายุ** (`401`) ให้แจ้งเตือนและ Redirect ไปหน้าเข้าสู่ระบบอย่างราบรื่น
- [ ] เชื่อมต่อระบบ **Payment Gateway** จริงพร้อมรองรับ Webhook
